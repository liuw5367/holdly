# Holdly 可靠性与月计划成员分组设计

## 目标

本轮工作同时解决现有业务可靠性缺陷和月计划多人数据的可读性问题。完成后，资产子资源操作具备完整的用户归属校验，提醒、金额、订阅状态和以旧换新遵循统一规则；月计划详情页与编辑页按成员分组，并在每个成员组头部单行展示收入、支出和净额。

## 非目标

- 不支持多币种换算。
- 不增加成员预算、成员转账、分组折叠或拖拽排序。
- 不重写计划数据模型。
- 不进行全站视觉品牌重做。
- 不增加新的通知渠道。

## 一、资产子资源授权

所有维修、保修和订阅续费写操作必须先验证目标资产满足以下条件：资产存在、属于当前用户、`deleted_at IS NULL`。维修更新和删除还必须验证维修记录属于 URL 指定的资产。查询层写接口不得只接受未绑定资产与用户上下文的裸子资源 ID。

未登录请求重定向到登录页；无权访问或目标不存在统一返回 404，避免泄露资源存在性。维修记录仍按现有需求硬删除，其他用户数据继续软删除。

## 二、提醒规则

提醒优先级为：全局开关、单资产开关、单资产提前天数覆盖、全局提前天数。

- 全局关闭时不查询待提醒资产，不发送邮件。
- 全局开启但单资产关闭时，该资产不发送。
- 两级开关均开启时，使用单资产覆盖天数；没有覆盖时使用全局天数。
- Cron 和手动检查调用同一提醒处理函数。

日期计算显式接收 `today`。一次任务只生成一个当前日期并传递给所有计算，避免跨午夜不一致。测试使用固定日期，覆盖续费当天、月末、闰年、年付、过期日期重新推算、发送失败和重复执行。

## 三、金额边界

数据库 `numeric` 字段和表单使用十进制字符串传递。业务累计、加减、折算和除法统一使用 `currency.js`；只有图表输入层可以将最终结果转换为 `number`。展示统一经过金额格式化函数。

该规则覆盖 Dashboard、资产每日成本、订阅月度与年度折算、计划汇总、以旧换新、XLSX 和邮件备份。金额验证拒绝空值、负值、非有限数字、指数格式和超出 `numeric(12,2)` 范围的值。

## 四、以旧换新

### 字段语义

- `listPrice`：新设备标价。
- `tradeInPrice`：旧设备回收价。
- `purchasePrice`：用户实际支出，即标价减回收价。
- 旧资产净持有成本按购入价减回收价实时计算。

为资产增加可空 `list_price numeric(12,2)`。历史数据不回填；普通新建资产可不写该字段。换新资产同时保存标价与实际支出。

### 事务流程

服务端依次验证旧资产、日期、金额和关联配置的用户归属，然后在一个数据库事务中创建或取得换新标签、创建新资产、写入标签关系、关联新旧资产并标记旧资产已换新。任一步失败时全部回滚。

换新日期不得早于购买日期或晚于今天；标价和回收价必须非负；实际支出不得为负；旧资产必须是当前用户仍在持有的买断型资产。客户端提交的派生金额不作为事实源。提交按钮在请求进行中禁用，服务端拒绝对已经换新的旧资产重复执行。

## 五、订阅有效状态

使用共享纯函数根据 `subscriptionStatus`、开始日期、停止日期和 `today` 计算有效状态。未来停止日期在到期前仍视为活跃；到期日的计费边界遵循现有半开区间规则。Dashboard、资产列表、详情页和提醒任务使用同一状态函数，不各自判断字段。

## 六、月计划成员分组

### 数据模型

不修改计划数据库结构。`plan_record_items.member_id` 表示金额归属成员，直接作为分组键。读取层产生派生结构：

```text
PlanRecordMemberGroup
  member
  incomeItems
  expenseItems
  totalIncome
  totalExpense
  netIncome
```

小计全部使用 `currency.js`。当前用户排第一，其余成员按计划成员顺序排列；已退出但仍有历史条目的成员排在最后。详情页隐藏完全没有子项的成员，编辑页保留所有当前成员以便新增条目。

### 详情页

页面顶部保留整月收入、支出和净额。下方从“收入区、支出区”改为成员卡片。

每个成员组头部显示头像、昵称和单行汇总：

```text
收入 12,000 · 支出 8,000 · 净额 +4,000
```

净额正数使用成功色，负数使用错误色，零使用弱化色。组内先显示收入子项，再显示支出子项；空的子区不渲染。成员备注移动到对应成员组底部。

在窄屏上，成员名称与汇总可以上下排列，但三个汇总值保持在一行，不截断数字，也不引入横向滚动。

### 编辑页

编辑页与详情页使用相同的成员顺序和组头汇总。金额输入变化后，小计即时重算，不写入提交 payload。

每个成员组内分别提供“添加收入项”和“添加支出项”，新增函数显式接收 `memberId` 和 `itemType`。`own` 权限下仅当前用户组可编辑，其他成员组保持正常可读并显示“只读”，不再通过整体半透明表达权限。`all` 权限下所有当前成员组可编辑。

服务端继续执行成员权限校验和乐观锁。客户端分组不能改变现有安全边界；伪造 `memberId` 必须被拒绝。

### 共享边界

分组和小计由纯函数统一生成，详情页和编辑页复用。组头和汇总可以抽取轻量展示组件；只读条目和编辑输入行保持独立，避免万能组件。

## 七、Dashboard 与货币展示

Dashboard 指标名称明确时间和口径：今日持有成本、每月订阅支出、当前持有数量、持有资产原值、近一年成本分布、近六个月成本趋势。

当前版本明确固定人民币。页面金额统一展示 `¥`，邮件使用“元”，XLSX 标注币种。暂不增加用户币种设置。首次登录和空状态继续以添加第一件资产为首要路径；计划模块不并入资产 Dashboard。

Dashboard 桌面内容宽度允许扩展至约 960px，详情和表单保持较窄阅读宽度。禁用状态不能只依赖透明度；数字使用稳定宽度和等宽字体。

## 八、数据流

```text
Loader / Action
  -> 认证与输入解析
  -> 用户归属及业务规则校验
  -> 查询层事务或纯读取
  -> 领域纯函数计算金额、日期、状态、成员分组
  -> 路由视图模型
  -> 页面展示与交互
```

路由不直接拼接复杂金额或状态规则。查询层负责数据一致性，纯函数负责可测试的业务推导，页面只维护输入状态与呈现。

## 九、测试与验收

每个行为变更先添加失败测试，再写最小实现使其通过。

自动测试覆盖：越权维修操作、全局提醒开关、提醒日期边界、金额精度、换新事务回滚、换新输入校验、订阅未来停止日期、成员分组排序、成员小计、退出成员历史数据、`own/all` 权限和乐观锁。

人工验收覆盖：资产新增、编辑、出售、换新、删除；维修和保修；订阅取消、恢复、续费；Cron 与手动提醒；Dashboard；月计划 2、5、10 个成员；单成员 20 个子项；桌面和 375px 移动端；XLSX 与邮件备份。

最终验证命令：

```bash
pnpm test
pnpm typecheck
pnpm lint
pnpm build
```

## 十、交付顺序与回滚

任务按以下顺序独立提交：设计文档、资产子资源授权、提醒可靠性、金额统一、以旧换新、订阅状态、成员分组读取模型、月计划详情页、月计划编辑页、Dashboard 与货币、文档收尾。

每个提交都应处于可运行状态。无 schema 变更的任务可以直接回滚对应提交。`list_price` 为可空新增字段，旧代码可忽略；回滚应用代码时无需立即删除字段。只有确认没有新版本依赖该字段后，才允许执行数据库降级迁移。

## 十一、关键假设

`plan_record_items.member_id` 表示金额归属人，而不是录入人。当前默认子项、编辑权限和保存逻辑都支持这一解释。如果未来需要区分归属人和录入人，应单独增加创建者字段，不改变本轮分组口径。
